## Decisões

- **DEC-002** — reescrever o scoring fuzzy: abandonar `token_set_ratio` (infla score com subconjunto) por score ponderado (token_sort + WRatio + penalização de comprimento + bônus de medida). Implementação no motor v2.
- **DEC-003** — GUI em abas + 2 QThreads (formalizado).

## Bugs

- **FIX-002** — renomear+copiar/mover copiava sobre si mesmo sem pasta destino; resolvido checando se a pasta final difere da origem.

## Aprendizados / armadilhas
- `token_set_ratio` retorna 100 quando uma string é subconjunto da outra → fonte da inflação de score (virou armadilha #1 em CONTEXT e DEC-002).
- Códigos de fabricante não têm comprimento estável entre sistemas → match por código deve ser bidirecional (armadilha #4).
- Operações compostas (renomear+X) precisam tratar o caso degenerado sem destino (armadilha #5).
- Não há melhor scorer universal — exige golden set para medir antes de calibrar.
